## Architecture Decisions

- Leaderboard aggregates (innings, BF, 4s, 6s, NOs, overs, runs given, 3WI, 5WI, 50s, 100s) are computed server-side in `/api/players` GET by joining `score_entries` in JS, rather than client-side N+1 fetches; `computed_stats` trigger-maintained fields remain the source for runs/wickets/averages/economy/HS/BBM.
- Added Sidebar component in TopNav for clean access and visibility.
- Responsive navbar 2026-09-12: `components/ui/TopNav.tsx:25` desktop `nav` `hidden lg:flex` with OVERALL STATS/MANAGE PLAYERS + ASK LYST inline (single top navbar >=lg), `components/ui/Sidebar.tsx:58` drawer `lg:hidden` wrapper so hamburger + drawer only <lg (mobile/tablet); both nav variants share `#b9e03c` animated underline `w-0 → w-full duration-300` on `group-hover`.
- Tool-selection reasoning in `assistantOrchestrator.ts` runs at `temperature: 0` rather than default sampling temperature — tool dispatch is treated as a near-deterministic classification decision, not a creative-generation task, to eliminate variance in reasoning-path length and tool-call correctness.
- Duplicate tool-call detection (`lib/duplicateCallDetect.ts:31`) and the forced-final-round fallback (disabling tool calls via `FunctionCallingConfigMode.NONE` on the last round) are noted as defense-in-depth in history, but the current `lib/assistant/assistantOrchestrator.ts:99` throws `MAX_TOOL_ROUNDS exceeded` on the final round rather than forcing a text-only turn; `temperature: 0` was the actual root-cause fix for the observed failures.
- `matches` table (new `/matches` fixtures/results feature) is standalone with no FK into `score_entries` — chosen over a `match_id` FK design because opponent teams keep growing and a select/dropdown of opponents would become unusable to scroll. `team_2` is stored as free text on `matches`; `score_entries` is untouched (no new columns, no trigger changes).
- Assistant matches boundary (2026-09-23): `lib/matchesQueryTool.ts` isolates 2 new tools `get_team_record`/`query_matches` as their own module — does NOT extend `query_team_data` allowlist. `query_team_data` remains allowlisted only to `players`/`score_entries`/`computed_stats`; `query_matches` allowlisted only to `matches` columns `match_date`, `team_2`, `match_type`, `location`, `match_result`. `lib/assistant/assistantSystemPrompt.ts:57` enforces no-join rule: correlating a `matches` row with `score_entries` is unavailable by design, must not be faked via `match_date`.
