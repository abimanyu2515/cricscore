## Architecture Decisions

- Leaderboard aggregates (innings, BF, 4s, 6s, NOs, overs, runs given, 3WI, 5WI, 50s, 100s) are computed server-side in `/api/players` GET by joining `score_entries` in JS, rather than client-side N+1 fetches; `computed_stats` trigger-maintained fields remain the source for runs/wickets/averages/economy/HS/BBM.
- Added Sidebar component in TopNav for clean access and visibility.
- Responsive navbar 2026-09-12: `components/ui/TopNav.tsx:25` desktop `nav` `hidden lg:flex` with OVERALL STATS/MANAGE PLAYERS + ASK LYST inline (single top navbar >=lg), `components/ui/Sidebar.tsx:58` drawer `lg:hidden` wrapper so hamburger + drawer only <lg (mobile/tablet); both nav variants share `#b9e03c` animated underline `w-0 → w-full duration-300` on `group-hover`.
- Tool-selection reasoning in `assistantOrchestrator.ts` runs at `temperature: 0` rather than default sampling temperature — tool dispatch is treated as a near-deterministic classification decision, not a creative-generation task, to eliminate variance in reasoning-path length and tool-call correctness.
- Duplicate tool-call detection (`lib/toolCallTracker.ts`) and the forced-final-round fallback (disabling tool calls via `FunctionCallingConfigMode.NONE` on the last round) are retained as defense-in-depth safeguards against a genuinely stuck loop, even though the temperature fix was the actual root-cause resolution for the observed failures.
